MCP client

The /mcp endpoint speaks MCP over Streamable HTTP, at the 2026-07-28 revision of the spec; older clients are still answered on the same URL. It authenticates with the bearer token above — no OAuth — which is what decides the shape of the config below. In both blocks the token is masked; Copy puts the real one on your clipboard.

Claude Code, Cursor, VS Code

Anything that connects to an MCP URL itself. Goes in .mcp.json (or ~/.claude.json). "type" is not optional: an entry carrying a url and no type is read as a local command that isn’t there, and the server is skipped.

{{.MCPConfigShown}}

Or let the CLI write it:

claude mcp add --transport http dtcom {{.BaseURL}}/mcp \
  --header "Authorization: Bearer {{.TokenMask}}"

Claude Desktop

claude_desktop_config.json starts local programs and has no url key at all — paste the block above into it and it is rejected as the wrong shape. Remote servers normally go in under Settings → Connectors → Add custom connector, but that asks the server to run an OAuth flow, and this one takes a bearer token instead. So run mcp-remote as the local program and let it carry the header for you. Needs Node.

{{.MCPDesktopShown}}

The header sits in env rather than inline in args on purpose: Claude Desktop on Windows does not escape spaces inside args when it launches npx, so Bearer … arrives mangled. Split this way the only space is in an environment variable, and mcp-remote expands ${DTCOM_TOKEN} itself. Restart Claude Desktop fully after editing the file.

REST API

Send the token as Authorization: Bearer <token>. Bodies and responses are JSON.

curl -H "Authorization: Bearer $DTCOM_API_TOKEN" \
  {{.BaseURL}}/api/v1/articles

curl -X POST {{.BaseURL}}/api/v1/articles \
  -H "Authorization: Bearer $DTCOM_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"A new post","body":"# Hello\n\nBody text.","tags":["essay"]}'
